## 0. 裁定（均已拍板）

| # | 裁定                                          | 含义                                                                                                                    |
| - | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| ① | **服务运行时 = Rust**（方案 B：Rust 接管 · 保留 HTTP 契约） | box-service（11.2k 行 Node）逐步迁入 Rust 进程内服务，**HTTP 契约不变** ⇒ 前端与 e2e 零改动；迁移走**反代渐进**（F 组）。node 仅为**过渡**依赖（A3），F5 完成后从包内删除 |
| ② | **引擎运行时 = 用户自装，我们只检测**                      | Python venv / 依赖由用户按文档安装；我们负责「说得清缺什么 + 装法给得出」                                                                         |
| ③ | **模型 = 用户下载，我们校验建链**                        | 下载可交给用户；HF 目录布局与硬链接**用户做不对、且做错了不报错**（D-99）⇒ 校验 + 建链必须留在我们侧（C2）                                                        |

**方案 B 可行的三个实证**（2026-10-13 实测）：

1. 前端 **24.5k 行 TS/TSX，`fetch(` 调用数 = 0** —— 一律 `invoke` 走 Tauri IPC；`app/src-tauri/src/commands.rs` 是**唯一出口**（`api_get` / `api_post` / `api_delete` / `api_post_multipart` / `api_bytes` + `X-Box-Token`）。
2. box-service **零 npm 依赖**（根 `package.json` 无 `dependencies`）—— 纯 Node 标准库 + JSON 文件存储，无 SQLite、无原生模块。
3. Rust 侧现成设施：`music/` 模块 **14.6k 行 / 95 条命令**已在 Rust；`axum` / `tokio` / `reqwest` / `dirs` 已在 `Cargo.toml`；进程组信号（`kill(-pgid)` / `taskkill /T`）`service.rs` 已有。

⇒ 要搬的只有 **11.2k 行业务逻辑**（`server.mjs` 2673 / `store.mjs` 1918 / `engine-client.mjs` 894 / `config.mjs` 851 / 其余 ~4800），外围两层都是白送。

### F 组 · 服务 Rust 化（**主线**，P0）—— 目标：**彻底去掉 node**

> **反代渐进**：Rust 进程内服务先行，未迁移端点 `reqwest` 转发给 Node box-service（Node 退化为遗留后端），迁一个摘一个 ⇒ `commands.rs` 一行不改、e2e 全程不换靶子、任一端点失败把转发加回去即回退。>

**F 组已收口（2026-10-13）**：F1–F5 全部 ☑。「摘除 Node」摘的是**产品运行时与随包**，
不是仓库源码 —— `service/src/*.mjs` 仍留在仓库里，作为 `check:store` / `check:store-exec` /
`check:engine-parity` / `check:engine-http` / `check:translate` 五组**同源对拍**的对照端
（删掉它会连带作废这五组钉子）。因此 A3（node 随包）与 E1 的 node 签名项**明确作废**、不再做。

## 4. 风险

| #       | 风险                     | 说明                                                              | 缓解                                                                                   |
| ------- | ---------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **R1**  | 🔴 **检测与实际启动不一致**      | 路径推导写两份 ⇒「检测说没装、启动却起了」或反过来；两者**都看起来在工作**，没有断言就抓不到               | B3 + F2 强制单源：检测与 `resolveEngineLaunch()` / `defaultEnginePython()` 共用同一份推导，验收当场逐字节比对 |
| **R2**  | 🔴 **迁移期双轨失联**         | Rust 报 502 而 Node 遗留后端已挂 ⇒ 用户只看到失败，无人知道根因                       | F1 验收要求 Node 侧健康对 Rust 可见；转发失败时错误文本带出「遗留后端」状态                                        |
| **R3**  | 🔴 **F5 漏摘转发分支（静默失败）** | 功能照常、e2e 全绿，但 node 永远删不掉 —— 包里永久躺 36 MB + 一份没人调的 Node 服务        | F5 用**显式计数**白名单断言（「仍有 N 条转发」即红），不许靠「看起来迁完了」                                          |
