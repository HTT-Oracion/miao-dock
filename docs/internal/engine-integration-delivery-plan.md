**环境陷阱（三条，都会"报错得像别的问题"）**：
1. **主机的删除守卫会让 manga-service 建单 500** —— 服务的可写性探针 `writeFileSync`→`unlinkSync`，
   unlink 被拦下抛**非 errno 错误** ⇒ 按设计变成 500。**取证物：失败后 `root/` 里留着 `.write-probe-*`。**
   解法：跑验收时 `CODEBUDDY_SAFE_DELETE_ENABLED=0`（**不改产品代码**）。
2. **`MIAO_E2E_TMP` 不能指 `/tmp`** —— 服务端落盘黑名单会直接退出（症状是"服务未在 20000ms 内就绪"）。
3. **本机 Python 侧文件中介会换掉错误类型**：`os.mkdir` 对**已存在**目录本该抛 `FileExistsError`，
   却被抛成**包着 `EEXIST` 文案的 `PermissionError`** ⇒ 按正确 errno 忽略"已存在"的调用方（pip 解包 sdist）接不到。
   解法：`.tmp/engine-test/pip-mkdir-fix.py`（**只在该目录确实存在时**纠正类型 ⇒ **不放大权限**）。

## 2. 人员分工与职责

### 2.1 先把现实说清楚

`git log` 的 **103 次提交全部来自同一人**（`lvjinbin`）。本项目**当前没有多人团队**，不存在可以点名派活的第二、第三个人。
因此分工按 **「角色 × 执行体」** 划分——角色是**职责边界**，执行体是**实际承担者**。**不虚构人名。**

### 2.2 角色表

| 代号 | 角色 | 执行体 | 核心职责 | 权限 |
|---|---|---|---|---|
| **R1** | 产品负责人 / 验收人 | 用户（lvjinbin） | 拍板、真机验收、**最终接受或拒收**；GUI/手感类唯一见证人 | **否决权**；只有他能宣布"验收通过" |

## 5. 验收环节的组织方式与流程

### 5.1 三级验收（**缺一级不算通过**）

| 级 | 名称 | 谁做 | 做什么 | 失败信号 |
|---|---|---|---|---|
| **L1** | 自动断言 | R2 | `AGENTS.md` §3 命令；**正向 + 反证**；条数写死、跳过必须非零退出 | 有跳过 / 分母未写死 |
| **L2** | 独立复核 | **R3** | **换上下文、换执行体**重新回读代码，用**不同判据形态**验证同一条机制 | 换个判据就查不出来 |
| **L3** | 真机人工 | **R1 / R6** | 只能由人确认的项（观感、手感、"翻译得对不对"） | 用断言替代人工结论 |

**L2 专猎「假绿家族」五类**（本项目的既有教训，逐条对照）：
① 只判存在、不判唯一；② 子串命中；③ 注释/声明冒充实现；④ 恒红（看着覆盖、实则空转）；⑤ 两条反证共用一条断言。

### 5.2 阶段验收流程（每个 M 走同一条流水线）

1. **R2 自检** → 跑 §3 受影响命令 → 全绿；
2. **R2 跑反证轮** → 必须变红，且分母写死；
3. **R2 出交付说明**（一页）：交付物清单 + 实测数据 + 未验证项；
4. **R3 独立复核**（重点：新断言是否真的可反证）；
5. **R3 提异议 → R2 修 → 回到 1**（**不得靠放宽断言转绿**）；
6. **R1 验收**：看交付说明 + 抽验关键项（自动项看输出、人工项自己点）；
7. **R1 判定**：接受 → 独立 commit + 台账 `D-xx`；拒收 → 写明理由，回到 3。

### 5.3 拒收条件（出现任一即拒收）

- 反证轮出现**跳过**、**假阳性**，或**分母未写死**；
- 断言被**放宽**以便转绿（应改实现或改口径，并说明原因）；
- **未验证项被写成"已完成"**；
- 交付物**缺实测数据**（只有"类型检查通过"）；
- 文档条数未与脚本对账（`check:docs` 红）；
- 触碰 `vendor/` 参考实现，或改动方案文档**既有章节编号**。

### 5.4 变更控制

- **契约变更** → 回写《03》+ 留 `D-xx`，且需 R1 知情（影响插件）；
- **方案冲突** → 以《09》/《04》为准，偏离必须留 `D-xx`；
- **新增依赖** → 按 `AGENTS.md` §2-7，在提交信息与台账写清代价（体积 / 包数 / 平台耦合）。

### 5.5 留痕与可复现

- 台账 `docs/internal/spec-notes.md`，**编号接续**（当前到 D-56 ⇒ 本项目新条目从 **D-57** 起，不得重复编号）；
- 验收命令与**原始输出**写进交付说明；
- 探针与脚本必须可复现（例：`node .tmp/engine-test/probe.mjs`）。
