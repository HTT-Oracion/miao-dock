## 0. 命名

| 项 | 取值 |
|---|---|
| 产品名 | **喵坞 · MiaoDock** |
| 仓库目录 | `miao-dock` |
| 与插件关系 | 同族（插件「喵译 MiaoTrans」↔ 桌面端「喵坞 MiaoDock」），共用同一套设计令牌与品牌图形 |

**命名理由**：坞是船停靠、常驻待命之所——正好对应 Box 在产品里的真实角色：它不是「另一个翻译客户端」，而是**本地服务的宿主与可视窗口**，托盘常驻、随叫随到（《02》§1.1 / §2.1）。同时「坞」隐含了「集群/泊位」的容纳语义，与它托管 `manga-service` 的唯一入口地位一致。中英文都好念、无歧义、无负联想，且与「喵译」一眼可辨为同一套产品。

## 2. 技术实现思路

### 2.1 架构（严格遵循《02》§2）

```
喵坞 MiaoDock（Tauri v2 壳）
├── 应用外壳（WebView：Vite + React + TS）
│   ├── 侧边导航 78（徽标 + 应用入口 + 服务状态点 + 设置）
│   └── 应用区：漫画翻译应用（队列 / 漫画库 / 本机投放）
├── Rust 层（src-tauri）
│   ├── ServiceManager：子进程生命周期 + 四态机 + 端口探测
│   ├── 托盘（TrayIcon）：常驻 + 状态点 + 退出二次确认
│   └── 窗口策略：CloseRequested → hide()
└── 子进程
    ├── manga-service（Node，127.0.0.1:5180–5190）← 唯一翻译入口、队列、编号、落盘
    └── engine: mangatranslator-mock（Node，127.0.0.1:自动探测，默认 5003）← sidecar
```

### 2.2 三个关键实现裁决

| # | 裁决 | 理由 | 留痕 |
|---|---|---|---|
| R-a | **服务层用 Node 实现，作为 Tauri 的子进程拉起**（而非 Rust 重写） | 契约的服务端语义（NFKC 规范化、三层模型、幂等续做、SSE）与插件端的 mock 实现同源；用 Rust 重写等于把已验证的契约实现推倒重来，收益为零、风险极高 | D-07 |
| R-b | **本迭代运行时取系统 `node`**（本机 v22 已具备）；「自带 Node 运行时」列为 v2 | Tauri 不自带 Node 运行时。打包自带运行时（sidecar 方式）需额外 ~50MB 需在打包阶段解决，不影响本轮功能与验收 | D-08 |
| R-c | **真实 `mangatranslator` 未就绪 → 用模拟引擎 sidecar 顶替** | 真实模型（~2.8GB）与协议均不可得。模拟引擎实现 **同一 HTTP 边界**，可完整跑通「建单 → 排队 → 逐张翻译 → 落盘 → SSE 推送」，真实引擎接入时只换适配层 | D-09 |

**服务与窗口解耦的落地方式**：Rust 侧持有子进程句柄（`Child`），窗口 `hide()` 不影响子进程；应用退出时显式 kill 并等待端口释放。这使《02》§2.1「服务生命周期 = Box 进程生命周期」结构性成立，而不是靠约定。

### 2.3 复用既有资产（不重复造）

| 资产 | 来源 | 复用方式 |
|---|---|---|
| 契约服务端实现 | `miao-trans/mock-service`（已验证：真落盘、任务清单持久化、幂等表、路径三次校验、端口探测、SSE） | **提取为 `service/` 并「去伪造」**：根目录改 `~/Pictures/Box 漫画`、令牌改 CSPRNG 落 0600 文件、翻译改走真实引擎适配层、补 `ServiceManager` 需要的启动参数 |
| 设计令牌（18 色 Light/Dark + 圆角 + 字体分工） | 插件 `extension/src/theme/tokens.ts`（与设计稿变量集 `3:2` 逐字一致） | 直接迁入 `src/theme/tokens.ts`，保证「与插件共用同一套令牌」（《02》§5） |
| 品牌图形 | 方案文档 `logo/`（7 档 PNG + SVG 母版） | 迁入 `src/assets/`，托盘图标取 32/64 档 |

> **注意**：`miao-trans/mock-service` **保持原样不动**——它是插件端 27 项 e2e 的测试替身（固定令牌 + `.runtime` 目录 + 伪造图片），不能被「真实化」污染。Box 用的是它的**契约实现**，不是它的运行实例。

### 2.4 前端技术选型

Vite + React 18 + TypeScript，样式用**原生 CSS + CSS 变量**（`cssVars(mode)` 生成 18 组令牌），理由：① 令牌已是 CSS 变量形态，零转换成本；② 避免引入 Tailwind 造成与设计稿「逐字对账」的偏差；③ 组件树浅（单应用 + 3 视图），不需要额外状态库，用 `useReducer` 即可。

## 4. 验收标准

### A. 契约符合性（服务层 · 自动化断言）

| # | 验收项 | 判据 |
|---|---|---|
| A1 | 端口段探测 | `5180` 被占 → 升 `5181`…`5190`；全段被占 → **启动失败并明确报错**（不静默越段） |
| A2 | 健康检查 | `GET /health` 免鉴权；`service === "manga-service"`；`status ∈ ok\|degraded\|starting` |
| A3 | 鉴权 | 缺/错 `X-Box-Token` → `403 PERMISSION_DENIED`；非白名单 `Origin` → 403，**同一错误码不泄露哪项失败** |
| A4 | 批量上限 | 单请求 21 张 → `400 BATCH_LIMIT_EXCEEDED`，`details.limit=20 / submitted=21` |
| A5 | 幂等 | 同 `idempotencyKey` 24h 内重复 `POST /tasks` → 返回**同一 `taskId`**，不新建、不报错 |
| A6 | 漫画名规范化 | 10 步管线逐条：`第12话/学园祭`→`第12话学园祭`；`ＣＯＮ`（全角）→拒绝；`CON.txt`→拒绝；65 字→拒绝；`///`→`COMIC_NAME_REQUIRED`；尾部 `.`/空格剥离；NFKC 折叠 `１２３`→`123` |
| A7 | 编号 | 续编号 = 目录内 `^\d{3}\.(png\|jpg\|jpeg\|webp)$` 最大 N + 1；超 999 → `409 SEQUENCE_OVERFLOW` |
| A8 | 落盘 | `001.png` / `001_translated.png`；**永不覆盖**；`queued` 态下目录**不存在**（惰性创建） |
| A9 | 幂等续做 | `NNN_translated.*` 已存在 → item `skipped(already_exists)`，**序号不变** |
| A10 | 取消语义 | `running` 取消 → 等当前张跑完；**未开始**的 item `skipped` 且原图也不落盘（用户没轮到的页不在磁盘上留任何东西）；已处理的页按 G-11 保留；磁盘账目自洽（原图数 == 成功 + 失败）；**上传字节的暂存区被清干净**（未处理页的字节不留孤儿，G-12）；`keptItems` = 成功且已落盘的**译文**数，与实际一致 |
| A11 | 状态机 | Task 6 态 / Item 5 态按契约迁移；终态追加批次 → `409 TASK_NOT_APPENDABLE` |
| A12 | SSE | 四类事件齐备；`heartbeat` 每 15s；带 `Last-Event-ID` 可续传、不重放已推事件 |
| A13 | 队列 | 纯 FIFO 无插队；`GET /queue` 是位次与 eta 的**唯一来源**（客户端不估算） |
| A14 | 安全 | 路径三次校验任一失败 → 403 + 安全日志；伪造 `filename="evil.png"` 但字节是 WEBP → 落盘扩展名取**嗅探结果**；根目录黑名单（`/`、`C:\`、家目录本身、`/tmp`、系统目录）拒绝 |
| A15 | 任务列表（**契约外增量**） | `GET /tasks` 返回 running → queued → 终态（`finishedAt` 倒序）；终态行**留在列表里**（X-C1 的历史行来源）；来源归因取 `X-Box-Client`（`extension/*`→`extension`／`box-desktop/*`→`desktop`／缺省→`unknown`）；`status`/`limit` 过滤正确且 `limit=0 → 400`；**新增端点不得污染 `/queue` 语义**、不得改变 §5.2 响应形状；跨重启靠 `STATE_DIR/tasks/*.json` 恢复。依据见 `docs/internal/spec-notes.md` G-04 |
| A16 | 漫画库 | `GET /library` 逐漫画给出 `imageCount`/`translatedCount`/`byteSize`，且 `byteSize` **等于目录内所有文件字节数之和**（G-01 口径，与磁盘实测一致）；顶层 `totalImages`/`totalBytes` 为全库聚合；原/译文件流同 `seq` 可用；不存在的 `seq` → `404`（不返回空文件）；`reveal` 返回实际目录；受鉴权保护 |
| A16b | 漫画库·逐页集合（**契约外增量**） | `translatedSeqs` / `missingSeqs` **逐页精确**，且**双向反证**成立：中间缺口（003 有原图、无译文）下旧的「`seq <= translatedCount`」代理给出 `[1,2,3]`、事实是 `[1,2,4]` —— 第 3 页**假阳性**（没有译文却报已译）、第 4 页**假阴性**（有译文却报待译），两个方向同时错；`seqMax` 不因缺口被截断；外部删掉一张原图后 `missingSeqs` 精确为 `[2]`（「缺页」态仍可达）。依据见 `docs/internal/spec-notes.md` G-10 |
| A17 | 本地续做（**契约外增量**） | `GET /library/{name}/resume` 只列出「有原图、缺译文」的页；`POST` 建单后进入**同一条**串行队列；**不新增原图编号、不改动已存在原图的字节**（§7.2 永不覆盖）；无缺页 / 指定已有译文的页 → `404`；`seqs` 非数组 → `400`；受鉴权保护。依据见 `docs/internal/spec-notes.md` G-07 |
| A19 | 失败页保原图（**裁定增量**） | 引擎失败的页，**原图落盘**、不留译文（3 原 + 2 译 = 5 个文件，而非 4 个）；`/library` 把它算作「待译」（`missingSeqs` **不含**它，否则库里会报成「缺页」＝像用户没给过这页）；`GET/POST /library/{n}/resume` 能列出并续做它；续做时失败原因是 `engine_*` 而非 `original_missing`（证明真拿到了原图）；续做不改动原图字节。依据见 `docs/internal/spec-notes.md` G-11 |
| A20 | 上传字节暂存（**裁定增量**） | 上传即把字节落一份到 `state/pending/<taskId>/`（**漫画目录之外**），而**漫画目录仍不存在**（§4.1 惰性创建 / §4.3 不提前留痕未被破坏）；`SIGKILL` 后原地重启，未落盘页的**原图被搬回漫画目录**、无译文、暂存区收干净；任务仍 `failed(service_restarted)`（姿态：不做后台自动续做，由用户点「继续翻译」）；库里是 **4 页 / `seqMax` 4**（修复前静默缩水成 1 页）、逐页集合全在「待译」、无一页「缺页」；清单 `[1,2,3,4]`、`POST /resume` 返 201、续做失败原因是 `engine_*` 而非 `original_missing`（证明送进引擎的是**恢复出来的**原图）。**反证**：偷走暂存再走一遍 → 漫画目录依旧不存在、库里连条目都没有（排除「救回另有来源」）。`A10` 另补「取消后暂存区被清干净」。依据见 `docs/internal/spec-notes.md` G-12 |
| A21 | 落盘根目录可写性（**契约 §2.2 `DISK_FULL`**） | 根目录去掉写位（`chmod 0500`）→ `POST /tasks` 回 **507 `DISK_FULL`**、`details.reason === 'EACCES'`（原因带得出来）、不留 probe 残留文件；**反方向**：用 `NODE_OPTIONS=--import` 注入一个**刻意不带 errno** 的探测写入错误 → 必须回 **500 `INTERNAL`** 而**不是** 507「磁盘满或权限不足」，且原因留在 `details.reason` 里。依据见 `docs/internal/spec-notes.md` D-19 |
| A18 | 子进程守护（**契约 B4 的异常分支**） | 父进程被 SIGKILL（不可捕获）后，子进程仍自行退出、端口释放；父进程健在时**不误杀**（跨 2 个看守周期）。harness 刻意让子进程 stdout 走**文件**而非管道，避免 EPIPE 冒充「看守生效」（反证：`MIAO_NO_PARENT_WATCH=1` 时该断言必失败）。依据见 `docs/internal/spec-notes.md` D-12 |

### B. 服务生命周期

| # | 验收项 | 判据 |
|---|---|---|
| B1 | 关窗不退出 | 点关闭 → 窗口隐藏；**进程存活**；此时用插件/curl 提交任务仍成功执行 |
| B2 | 托盘常驻 | 托盘图标在；状态点反映 `running/starting/stopped/error` 四态 |
| B3 | 退出确认 | 托盘退出 → 二次确认，文案含「退出后浏览器插件将无法提交翻译任务」 |
| B4 | 退出清理 | 退出后 `5180` 端口释放、子进程无残留（`ps` 无 `manga-service`） |
| B5 | 异常退出清理（**易漏**） | 主进程**被强杀 / 崩溃**（SIGKILL 不可捕获）后，子进程仍能自行退出、`5180`/`5003` 释放。依据见 `docs/internal/spec-notes.md` D-12；自测 A18 覆盖 |

**怎么跑（一条命令）**

```bash
npm run task -- selftest:app           # B1–B4 正向（期望全绿）
npm run task -- selftest:app:refute    # B1 的反证（期望「拿不到结果」）
```

B1–B3 原本只能靠人点，而本机未授予「自动化」权限（`osascript` 被 TCC 以 `-10004` 拒绝，
非沙箱模式同样如此），这三条就会一直悬着。现改由应用自身的 `MIAO_SELFTEST=1` 模式
**程序化触发同一条代码路径**：

- `window.close()` 触发的就是点关闭按钮所走的 `WindowEvent::CloseRequested`；
- 托盘走的是同一个 `tray_action()`，只是调用方从事件回调换成自检；
- 断言取的都是**运行时可观测量** —— 窗口可见性、端口是否仍有人监听、`/health` 是否应答、
  **关窗后真提交一张 40×60 的 PNG 能否跑到 `done`**、以及从**运行中的 WebView** 里读回
  确认层文本（`eval` + `location.hash` 回传，双通道）。

它同时驱动设置页的规格自检（C1–C7 与 B2d/B3a–c）并带回结果，所以那一项也不再依赖手点 ——
「界面与方案文档对得上」于是成了回归里的一条断言，而不是一句主观评价。

`--refute` 是**反证**：把「关窗」换成真退出后，这组断言必须拿不到结果。绿的那轮只有在
反证轮变红时才作数 —— 否则它可能测的是别的东西。见 `~/.workbuddy/skills/falsifiable-verification`。

### D. 端到端（真实进程 + 真实落盘）

| # | 验收项 | 判据 |
|---|---|---|
| D1 | 与插件同契约联调 | 插件提交 31 张 → **一个 Task 两个 Batch**，队列中占**一个**位置；`seqFrom/seqTo` 连续无重号 |
| D2 | 本机投放同队列 | 投放 21 张 → 进入**同一条**串行队列；>20 → 同一 `BATCH_LIMIT_EXCEEDED` |
| D3 | 落盘可见 | 翻译完成后 `~/Pictures/Box 漫画/<漫画名>/` 出现成对的 `NNN.png` + `NNN_translated.png`（31 原 + 30 译 = **61** 个文件：失败的页**留原图、不留译文**，见 G-11）；漫画库能看到；对照页可左右翻页；「打开目录」能唤起访达；**队列屏「重试」在 `partial_failed` 任务上真的可用**（走 `POST /resume`，旧语义下它会 404） |
| D4 | 时效 | 20 张在**时效预算**内完成（预算 = `MIAO_E2E_ITEM_MS` 单张基准 × 20 × 1.2 抖动 + 10s 管道余量；基准默认 300ms = 模拟引擎口径），且进度与 SSE 一致。**已不再写死 30s** —— 真引擎是秒级/张，写死会在接入那天必红（`docs/internal/spec-notes.md` D-58） |
| D5 | 漫画库逐页判定（**缺陷回归**） | 中间缺口时 `translatedSeqs` **精确**、且与旧的「张数代理」结论**双向相反**（一个方向的假阳性 + 另一个方向的假阴性）；失败页不得被判成「已译」、不得永远停在「加载中…」、也**不得被报成「缺页」**（那读起来像用户根本没给过这一页）。依据见 `docs/internal/spec-notes.md` G-10 |

**怎么跑（一条命令）**

```bash
npm run task -- e2e        # D1–D5：起真实 engine + 真实 service，真提交、真落盘
npm run task -- capture    # 截图取证（需屏幕解锁，见下）
```

`e2e` 与 `capture` 共用 `MIAO_E2E_TMP`（默认项目内 `.tmp/e2e/`）：端到端那轮的落盘产物
**故意保留**，正是截图要拍的真数据 —— 清理只发生在**下一次运行的开头**，所以先 `e2e` 再 `capture`。

`capture` 有三个环境前提，都不在方案文档里、各踩过一次（`docs/internal/spec-notes.md` D-15、D-16）：
显示器**唤醒**、屏幕**解锁**、两个脚本的临时路径**一致**。任一不满足时它会**拒绝出图并退出 2**，
而不是交出一批看起来「有产物」的假证据。

`selftest:app` 也一度要求屏幕解锁（规格自检里的 `requestAnimationFrame` 在窗口被遮挡时不触发，
结果静默归零）—— 那条已改成定时器兜底，现在**锁屏下也能跑出 12/12**，见 `docs/internal/spec-notes.md` D-17。
**验收不该因为没人看着就悄悄降级。**
