### 1.2 三个必须先解决的障碍

**① 断言体系把 `app.css` 当单一文件读。** 三个脚本都有文本判据（合计 20+ 处）：

- `music-platform-check.mjs:79` → `s.css`，含 `[^}]*` 取块、`@keyframes` includes、`transition` 时长跨句正则
- `units-structure-check.mjs:69` → `s.appCss`，`:886` 跨句取 `.di-capsule` 退场时长
- `settings-media-check.mjs:48` → `ctx.s.css`，`:530` 逐名 `includes`
- 反证条目里 `file: F.css` 与硬编码 `'app/src/styles/app.css'` 多处

拆文件后这些判据会**大面积变红**（不是真回归，是读不到文件了）。**这是本次改造的工程主体。**

**② 《09》有 4 处写着 app.css 的维护约定**（125 / 150 / 175 / 561 行），不改会与新规则自相矛盾。
顺带：175 行写的 `import '@styles/app.css'` 与实际 `@/styles/app.css` 不一致（vite alias 里没有 `@styles`），可顺手校正。

**③ 层叠顺序。** CSS 同特异性靠后定义者胜，切文件必然重排顺序。
**实测结论：无任何真实类名跨模块重复定义**（类名天然按模块隔离），且 §2.1 的文件顺序与原分区顺序逐段对齐
⇒ 拆分不产生层叠语义变化。该结论仍需在实施阶段用"构建产物字节 diff"硬验证，不能只信一次性脚本。

## 三、三条硬约束（要写进文档 + 加断言守护）

### 1. 本次不引入 nesting —— 保持与 CSS 等价的扁平语法

scss 在本阶段**只用于文件组织，不用于语法糖**，搬过去的规则与今天逐字相同。

原因不是审美，是断言：现有判据大量用 `[^}]*` 取块，nesting 会改变块结构 → 断言静默失效或恒红。
本项目已吃过"恒红比恒绿更隐蔽"的亏（用 JS 取体器取 Rust 函数体恒返 null），不能重蹈。

> **nesting 的取舍留待后续单独评估**，不作为本次的永久禁令。
> 届时前置条件：先给三个检查脚本装 SCSS AST 解析器（走 AST 取块替代正则取块），
> 且已拆好的分片本身不因嵌套而变简单。评估前，分片内一律保持扁平写法。

### 2. 设计令牌不出 scss

颜色 / 尺寸一律 `var(--md-*)`（运行时由 `theme/apply.ts` 注入），**scss 里不定义颜色、不用 SCSS 变量承载主题**。
这保住 `base.css` 注释里已有的承诺：「深色模式只换变量、不换结构」是**结构性事实**，要换主题只能改变量。
SCSS 变量只允许承载"纯重复的量值"（如断点），且必须注释写明用途。

### 3. 层叠顺序只在 `index.scss` 一处维护

模块文件之间**不靠顺序决胜**（无同名选择器），但 `index.scss` 的 `@use` 顺序仍需固定并加断言，防止有人随手调换。

## 四、断言改造（工程主体）

把三个脚本的 `readMaybe(F.css)` 换成**按 `index.scss` 声明顺序拼接 `styles/` 下所有分片**，产出与今天等价的单一文本。

- 判据逻辑**一行不改**（20+ 处 `match` / `includes` 全部照旧工作）
- 反证条目的 `file:` 改为定位到具体分片。scss 兼容 css 语法，**find/replace 文本不变**
- 新增守护断言（`STYLE.*` 组）：
  1. 每个 `styles/*.scss` 都被 `index.scss` 引用（防新增文件忘了注册）
  2. `index.scss` 的 `@use` 顺序 == §2.1 约定顺序
  3. 归属错位当场变红：`manga.scss` 里不出现 `music-`/`di-`/`settings-`/`set-` 前缀选择器，
     `music.scss` 里不出现 `qt-`/`lib-`/`notready`/`stage` 前缀（反之亦然，依此类推）
  4. 分片内不出现嵌套语法（选择器位置的 `&`）—— 守护 §三.1 的"本次保持扁平"
  5. 已删除的 `app.css` / `base.css` 不得复活（防有人改回单文件）

### 8.1 要写进《09》§2.4 的规则要点（供 S6 落笔）

1. 样式**只经 `index.scss` 一个入口**，`main.tsx` 不直接 import 分片。
2. 分片职责：`base` 重置与排版基座 / `app` 外壳与原子件 / `components` 跨模块公共件 /
   `<module>.scss` 单模块私有样式。
3. **新增模块 ⇒ 新建同名分片并在 `index.scss` 注册**，就放它自己的前缀选择器。
4. 模块私有样式**不得**放进 `app.scss` / `components.scss`（有断言守护）。
5. 分片内保持扁平写法（本次不用 nesting）；设计令牌一律 `var(--md-*)`，scss 不定义颜色。
6. `@use` 顺序按 §2.1，不得随意调换（有断言守护）。
7. 桌面歌词窗口不在本规则内（独立入口，样式内联）。
