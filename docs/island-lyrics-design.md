# 设计稿：歌词并入灵动岛（v1）

> 依据用户拍板：**砍掉桌面歌词开关与功能**，把歌词与灵动岛放在一起，不保留桌面歌词。
> 配套：待办清单见 `app-restore-and-lyrics-plan.md` §3.4（删除影响面）。

---

## 1. 一句话方案

**给灵动岛增加第 4 态「歌词卡」**：展开后歌词占据卡片主体，原有播放控件压缩到一行保留。

同时**不新增任何歌词偏好** —— 直接复用展开播放器那套（`lyricsHighlightColor` / `lyricsFontSize`），
因此桌面歌词的 4 个独立偏好（字号 / 高亮色 / 底色 / 行数）可以**整套删掉**，设置弹窗也随之取消。
这是本次合并最大的简化收益。

---

## 2. 状态机（4 态）

| # | 状态 | 尺寸 | 触发 | 内容 |
|---|---|---|---|---|
| 1 | 圆点 | 30 × 30 | 轻提示无文字时 / 音乐首帧 | 语义点 / 波形占位 |
| 2 | 胶囊 | 200 × 30 | 音乐**折叠**态 | 封面 + 歌名 + 波形 |
| 3 | 播放卡 | 320 × **150** | hover 展开（**默认视图**） | 封面 + 歌名/歌手 + 进度 + 控件 |
| 4 | **歌词卡**（新） | 320 × **150** | 展开态内点「歌词」切换 | **歌词 2 行** + 精简控件行 |

> 高度**保持 150 不变**：2 行歌词（约 48px）+ 控件行（约 44px）+ 内边距刚好放得下，
> 不需要动既有尺寸常量（改动越小越好）。
> 宽度保持 320，与既有常量一致，不与顶栏/侧栏打架。

```
  圆点 30×30          胶囊 200×30                播放卡 320×150            歌词卡 320×150
 ┌────┐         ┌──────────────────┐      ┌──────────────────────┐  ┌──────────────────────┐
 │ ●  │   →     │ ▣  歌名…      ▁▃▅ │  →   │ ┌────┐  歌名          │  │  ▶ 当前句（高亮·逐字）  │
 └────┘         └──────────────────┘      │ │ 封面│  歌手          │  │      下一句（暗）      │
                                          │ └────┘   ▁▃▅▂           │  ├──────────────────────┤
                                          │ 0:42 ━━━━━●━━━ 4:12     │  │ ⏮ ⏯ ⏭ 🔊  ▤播放  ⤢  │
                                          │ ⏮ ⏯ ⏭ 🔊  ▤歌词  ⤢     │  └──────────────────────┘
                                          └──────────────────────┘
```

**切换方式**：播放卡右下角的 `歌词` 图标按钮 → 歌词卡；歌词卡同位置变成 `播放` 图标 → 切回。
**记住选择**：用户上次选了歌词卡，下次打开音乐时直接进歌词卡（存进 `Prefs`）。

## 3. 歌词卡布局规格

| 区域 | 高度 | 内容 |
|---|---|---|
| 歌词区 | ≈ 48px | 2 行：**当前句**（在上，14px、高亮、颜色用 `--lyr-hl`）/ **下一句**（在下，12px、暗色） |
| 操作行 | ≈ 26px | 上一首 · 播放/暂停 · 下一首 · **歌词/播放切换** · 打开播放器 |

> 尺寸是**卡片自己的固定值**，不跟随设置页那条 17–48 的字号量程：
> 卡片只有 320px 宽，48px 一行放不下几个字、17px 又会把 150px 高撑满。
> 高亮色则**跟随** `lyricsHighlightColor`（用户选的颜色应当处处生效）。
> 可用高度核算：150 − 62(共享封面区) − 26(操作行) − 6(gap) − 8(下内边距) ≈ 48px；
> 两行 14/12 × 行高 1.35 + 8 gap ≈ 43px —— 纸面成立，**真机待验**。

- **当前句支持逐字推进**：复用已有的 `KaraokeLyrics` 双层 `width` 裁切方案，不再写第二份
- **行数固定 2 行**（当前句 + 下一句）：灵动岛空间有限，不做行数可调 —— 这正是删掉桌面歌词「行数」偏好的理由。
  ⚠️ 与桌面歌词的排法**刻意不同**：桌面歌词是「当前句在最下、往上回溯」，因为它在屏幕底部、眼睛自然往下找；
  灵动岛在屏幕顶部、且只有两行 —— 把当前句放**上**、把「即将唱什么」放下面更有用，也避免视线先扫到已唱过的内容。
- **超长句**：`nowrap` + 两端淡出（与折叠胶囊的 `is-clip` 同一套视觉语言），不做横向滚动
- **无歌词 / 纯音乐**：歌词区显示「♪ 纯音乐，请欣赏」，控件行不变；**不退化成空白**
- **暂停时**：当前句停在已推进的位置（不继续爬），与桌面歌词既有行为一致

## 4. 偏好策略（**这是最大的简化点**）

| 原来（桌面歌词） | 现在（灵动岛歌词） |
|---|---|
| `desktopLyricsFontSize`（独立字号 16–40） | ❌ 删 → 用 `lyricsFontSize`（展开播放器那套） |
| `desktopLyricsHighlightColor` | ❌ 删 → 用 `lyricsHighlightColor` |
| `desktopLyricsBaseColor` | ❌ 删 → 用 `--lyr-text`（按皮肤算好的正文色） |
| `desktopLyricsLineCount`（2–5 行） | ❌ 删 → 固定 **2 行** |
| `DesktopLyricsSettingsModal`（弹窗） | ❌ 删 |
| PlayerBar 的「桌面歌词设置」齿轮 | ❌ 删 |

> **收益**：少一套偏好（4 个字段 + 4 个 setter + 推送通道 + 弹窗 + 入口），
> 且用户只学"一套歌词外观"。**代价**：灵动岛歌词不能单独调外观 —— 但两处本来就不该有两套。

## 5. 交互细节

| 操作 | 行为 |
|---|---|
| hover 岛上 | 展开到上次的视图（播放卡 / 歌词卡） |
| 移开鼠标 | 收起为胶囊（24px 容错 + 全局 mousemove 兜底，既有逻辑不变） |
| 点 `歌词` | 切到歌词卡；**记住选择**并持久化 |
| 点 `播放` | 切回播放卡 |
| 点歌词区 | 不响应（避免误触）；双击岛体仍走既有语义 |
| 点 `⤢` | 打开展开播放器（既有） |
| 轻提示到来 | 按既有优先级：**轻提示 > 播放态**，提示结束后回到原视图 |

## 8. 待确认（2 个小问题）

1. ~~歌词几行？~~ **已定：2 行**（当前句 + 下一句）。卡片高度保持 150 不变。
2. ~~切换入口放哪？~~ **已定：右下角**（歌词态显示 `播放` 图标、播放态显示 `歌词` 图标，
   与「打开播放器」同处一行，切换键在前、⤢ 钉在行尾）。

### 补充说明（实施后才明确的）
- **歌词排法与桌面歌词相反**：桌面歌词在屏幕底部、可放多行，按"当前句在最下、往上回溯"；
  灵动岛在屏幕**顶部**且只有两行，用户是"往下扫一眼" —— 把"即将唱什么"放下面才是有信息的那一半。
- **歌词变量必须自己注入一遍**（`--lyr-hl` / `--lyr-text` / 字号）：
  灵动岛**不在** `.music-exp` 子树里，展开播放器注入的取不到。
  尤其 `--lyr-text` 不注入会回落 `#fff`，浅色主题下是"白字白底 = 完全看不见"。
- **逐字推进复用 `KaraokeLyrics`**（给它的 `windowSize` / `scroll` 两个可选 props），
  不再写第二份逐字实现。
