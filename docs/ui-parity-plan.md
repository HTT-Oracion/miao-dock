## 二、缺陷清单（P0 · 确定性，可立即修）

### D1 桌面歌词窗口位置计算错误 → 窗口出现在屏幕外

**症状**：点「桌面歌词」无反应（窗口实际已创建，开关也变「已开」，但看不见）。

**根因**（`app/src-tauri/src/lyrics_window.rs:90-113`）：

```rust
let h = app.primary_monitor()...map(|m| m.size().height as f64)  // ← 物理像素
(h - 160.0 - 80.0).max(0.0)                                      // ← 但用于逻辑坐标
.position(y, 0.0)
```

| 项 | 值 |
|---|---|
| `Monitor::size()` 返回 | **物理像素**（Retina 上 2×，如 1964） |
| `WebviewWindowBuilder::position()` 期望 | **逻辑像素**（如 982） |
| 算出的 y | `1964 − 160 − 80 = 1724` |
| 结果 | y=1724 **远超屏幕逻辑高度 982** → 窗口落在可视区域外 |

**控制者/归属**：本地窗口位置属**应用设置**，不应依赖显示器尺寸硬算。

**修法（推荐 A）**：
- **A（推荐）**：创建时**不指定 `position`**，位置交给前端 `restoreWindowPosition()` + Rust `clampToWorkArea()` 钳制到工作区 —— 与参考实现一致，且天然兼容多屏/分辨率变化
- **B**：保留 Rust 摆位但**除以 `scale_factor()`** 做物理→逻辑换算

---

### D2 `assetProtocol` 未启用 → 本地歌曲无法播放

**症状**：本地歌单已导入（导入只读文件系统，故能成功），但点播放无声/无反应。

**根因**：`app/src/music/store.ts:557` 用 `convertFileSrc(song._localPath)` 生成 `asset://` URL，
而 `app/src-tauri/tauri.conf.json` 的 `app.security` **只有 `csp: null`**，没有 `assetProtocol`。

Tauri v2 官方默认值（已核对文档）：

```json
"security": {
  "assetProtocol": { "enable": false, "scope": [] }   // ← 默认关闭
}
```

→ 生成的 `asset://localhost/...` 被 WebView 拒绝 → 本地歌曲必然播不了。

**修法**：

```json
"app": {
  "security": {
    "csp": null,
    "assetProtocol": {
      "enable": true,
      "scope": ["$HOME/**"]     // 需覆盖用户导入音乐的路径；如需更大范围再放宽
    }
  }
}
```

> ⚠️ `scope` 的宽度有安全含义（scope 内文件可被 WebView 读取）。`$HOME/**` 能覆盖常见音乐目录
> 与 `test-music/`；是否放宽到 `**` 需你确认。
